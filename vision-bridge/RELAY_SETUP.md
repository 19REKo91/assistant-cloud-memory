# إعداد ممر رد DeepSeek

## ما يفعله هذا الممر

- الصفحة: `/relay`
- واجهة API: `/api/sync`
- ملف الرد الوحيد الذي يمكن للمسار تعديله: `SYNC/DEEPSEEK_REPLY.md`
- لا يستطيع الطلب اختيار مسار آخر أو حذف ملفات.
- إذا لم تكن الأسرار مضبوطة، يرفض المسار الكتابة افتراضيًا.

هذا الممر لا يضيف أدوات إلى جلسة DeepSeek ولا يجعل جلسة ChatGPT تنضم تلقائيًا إلى محادثة خارجية. لا يزال نقل الرد من جلسة DeepSeek إلى الصفحة يدويًا في هذا النموذج الأولي.

## متغيرات بيئة Vercel المطلوبة

أضف المتغيرين في مشروع Vercel `assistant-cloud-memory` لبيئة Production:

1. `GITHUB_SYNC_TOKEN`
   - أنشئ Fine-grained personal access token من GitHub.
   - حدّد المستودع `19REKo91/assistant-cloud-memory` فقط.
   - امنحه صلاحية **Contents: Read and write** فقط؛ لا تضف صلاحيات Issues أو Pull requests أو Administration.
   - أدخل الرمز مباشرة في Vercel Environment Variables، وليس في GitHub أو هذا الملف أو أي محادثة.
2. `SYNC_WRITE_KEY`
   - أنشئ عبارة سرية طويلة وعشوائية لا تقل عن 32 حرفًا.
   - احفظها كمتغير بيئة حساس في Vercel.
   - أدخل هذه العبارة في حقل «مفتاح الكتابة» على صفحة `/relay` فقط. لا ترسلها إلى DeepSeek.

بعد إضافة المتغيرين، أعد نشر Production كي تصبح القيم فعالة. لا يلزم وضع أي سر في ملفات المستودع.

## ملاحظات أمان

- يتعامل المسار مع مسار ثابت واحد؛ لا يقبل اسم ملف من الطلب.
- رمز GitHub لا يصل إلى المتصفح؛ يستعمله الخادم فقط.
- مفتاح الكتابة منفصل عن رمز GitHub، ويجب عدم تضمينه في روابط URL.
- محتوى `SYNC/DEEPSEEK_REPLY.md` يصبح عامًا عبر المستودع. لا تستخدمه لمحتوى سري.
- لا تدّع نجاح الكتابة إلا بعد أن يؤكد GitHub نجاح طلب الحفظ.
